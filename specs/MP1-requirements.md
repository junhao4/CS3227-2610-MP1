# Project Description

In this project, you will develop a personal utility app while using LLMs and prompting as part of the software development process.

The expected level of work is similar to what you did in your individual project (iP) in CS2103/T. A trimmed version of the project description with AI Guidance is as shown in https://nus-cs2103-ay2627-s1.github.io/website/projectDuke/cs3227.htmlLinks to an external site..

(You are strongly encouraged to re-do the CS2103/T iP following the AI Guidance as a warm-up exercise for MP1.)

It is up to you to define the features of your app. However, the minimal bar for the functionality and complexity is your CS2103/T iP since the use of AI tools should allow you to accomplish more with the same level of work.

In addition, as you work on the project, you should reflect on the use of AI and create a reflection document.

Here are some sample questions that you can use to guide your reflections.

- Why was the prompt formulated that way?
- What assumptions did the LLM make?
- What did it get wrong?
- How did I verify the result?
- How did the prompt evolve?
- When was prompting less effective than manual work?
- What engineering judgement was still required?
- What would I do differently next time?

## Restrictions

- This is an individual project (i.e., no team submissions allowed).

- The app should be a Java desktop app as you have done in your CS2103/T iP.

- In general, you are expected to focus on using LLM & Prompting. However, you are also allowed to use the agentic development features mentioned in the AI Guidance in the CS2103/T iP.

- You are not allowed to replicate the functionalities of the CS2103/T iP or the team project (tP), which is a to-do manager with a chat interface. However, you can still do a chatbot that does something entirely different (e.g., a budget tracker with a chat interface).

- You will be asked to redo the project if you violate such restrictions.

- If you are unsure, please use the forum to clarify.

## Submission Instructions

For us to grade this assignment in a timely manner, we need you to adhere strictly to the following submission guidelines. They will help us grade the assignment in an appropriate manner. You will be penalized if you do not follow these instructions. 

The repo should be named as CS3227-2610-MP1 in your Github account and set to be public.

It should contain:

- Any source code. The code will be reviewed for code quality. (Please format it nicely. We would really appreciate it.)
- A user guide (docs/UserGuide.md). This should describe all current features of your system, and how the users can set up and test your system. Ensure those descriptions match the product precisely, as it will be used by peer testers (inaccuracies will be considered bugs).
- A developer guide (docs/DeveloperGuide.md). This should describe the design of your system and the relevant software engineering process. It should match the latest release of the product and include an acknowledgement section citing all ideas/code/documentation you have reused.
- A reflection document (docs/Reflections.md). This should contain your reflections on doing AI-assisted SE using LLM & Prompting. Give at least 3 examples of interesting prompts and explain them in detail.
- A folder of summary logs (logs/…). This folder should contain summaries of all the prompts and interactions that took place during the development of this app. Ask AI to produce the summaries for you, but don’t forget to verify the correctness of the generated summaries. (These summaries will come in handy when you reflect on your project.) 

Make sure that your repo is named and structured as explained in this write up, and master branch is up to date. We will pull the latest version of your master branch before the deadline, which is 1 Sep (Tue), 2pm SGT, and use it for grading.

You should also submit your Github username through the relevant Canvas quiz by the same deadline.

There absolutely will be no extensions to the deadline of this assignment. Read the Grading page in Canvas if you are unsure about the late submission penalty.

In addition, we will also access your repo on Github during the grading process so please make sure that the repo is accessible and there are no further changes to it after your submission.
